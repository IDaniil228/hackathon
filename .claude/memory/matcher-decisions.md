Сервис подбора `matcher/` описан в `docs/matcher/`: механика, безопасность, развёртывание, валидация с результатами бенчмарка. Новые решения сверять с этими документами

Решения владельца 2026-10-10:

- Отдельный сервис по образцу taskgen, работает в базе api своей ролью: таблицы `match.*` остаются в миграциях api, роль читает явный список колонок и таблиц из `matcher/db-init.sql`
- LLM-слой taskgen копируется скриптом `matcher/scripts/sync_llm.py`, а не выносится в общий пакет. Возражение Мии о втором источнике правды не снято; общие куски (`llm_config.py`, `evaluation/factcheck.py`) вынесены в taskgen, чтобы копия генерировалась без ручного дубля
- Неподтверждённый грейд всегда ниже подтверждённого, без коэффициента
- Город и формат работы префильтр берёт из связанной вакансии: у `hire.employer_needs` этих колонок нет, схему не меняли
- Фрагменты негативного промта кандидата в выдаче видит работодатель: это принято, не скрывать
- Малая фиксированная доля новых и случайных профилей (разведка) остаётся

Находки стенда, не записанные в репозитории:

- Ollama на nixos-pc слушает только `127.0.0.1:11434`, поэтому контейнеры Compose через `host.docker.internal` до неё не достают. LLM-прогон на стенде делали матчером на хосте (`uv run matcher serve`) против базы и taskgen из Compose
- Запись настоящих прогонов с полными промптами и ответами (GigaChat, deepseek-flash с рассуждениями и без) — артефакт https://claude.ai/artifact/4rqbJAnMgnWw5mmSZdz2e3. DeepSeek в режиме без json_schema на первом вызове часто отвечает не по схеме, и срабатывает повтор
- `llm_stage.enabled` по умолчанию выключен: без явного включения подбор идёт по факторам с шаблонными объяснениями

**Why:** решения и находки определяют, что менять в matcher можно, а что уже согласовано

**How to apply:** перед изменением порядка выдачи, прав роли или способа делить код с taskgen свериться с этим списком. Тесты matcher требуют и `MATCHER_DATABASE_URL`, и `MATCHER_TEST_OWNER_URL` (`docs/matcher/deployment.md`). Связано с [[taskgen-decisions]], [[taskgen-test-db]], [[llm-provider-compat]]
