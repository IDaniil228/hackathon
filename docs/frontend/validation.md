# Проверка Сцепки

## Процедура

Проверки интерфейса разделены по границе доказательства. Vitest проверяет HTTP-протокол, запрет автоматического повтора мутации, точную радиальную метрику и реестр незавершённых действий. Playwright проверяет поведение браузера, cookies, темы и реальные пользовательские сценарии

UI-проверка генерации использует контролируемые ответы API, чтобы воспроизводимо доказать запрет редактора до выдачи задания. Живые сценарии работают с отдельной PostgreSQL-базой, настоящими API, matcher, taskgen, Piston и локальным SMTP. Контролируемые ответы не входят в runtime-приложение

Проверки запускаются без повторов теста. Сначала фиксируется причина красного прогона, затем исправляется код или неверная предпосылка проверки. Успешный сборочный exit code отдельно не доказывает пользовательский сценарий

## Подтверждённые наблюдения

| Проверка | Наблюдение |
| --- | --- |
| HTTP и действия | Access передаётся из памяти; мутация не повторяется автоматически; незавершённый запрос сохраняет ключ без копии личного текста |
| Браузерная сессия | Вход, refresh после перезагрузки, dev proxy и путь cookie проверены реальным браузером |
| Работодатель | Настоящий подбор, обе карты, предложение с зарплатой и отправка сообщения прошли сквозной сценарий |
| Найм | Создание потребности, публикация вакансии, отклик, выдача задания, ответ, оценка и ответ кандидата в чате прошли браузерный сценарий |
| Кандидат | Регистрация, получение SMTP-письма, подтверждение почты, сохранение профиля, PDF, распознавание, привязка ФСП и опрос проверены через интерфейс |
| Большой набор | Faker создал 1200 профилей; повторное наполнение добавило 0 записей; проверенный прогон рассматривал 183 профиля и использовал bge-m3 |
| Роли PostgreSQL | API не читает приватный payload карты; matcher не изменяет профиль; обе роли используют общую блокировку |
| Приватность | Отзыв обработки создаёт сохраняемую операцию очистки; интеграционная проверка сохраняет более новые разрешённые векторы |
| Миграции | `alembic check` не обнаружил новых операций; функции и права дополнительно проверены отдельно |
| Контраст и темы | Используется проверенная бренд-система; переключение и сохранение темы, системный режим и мобильная ширина проверяются в браузере |
| Сборка | Контейнер Nginx собран; живой сценарий подбора прошёл также через production proxy с refresh после перезагрузки |
| Чувствительность проверки | Намеренное изменение радиальной метрики вызвало красный Vitest-прогон; после восстановления формулы проверка прошла |

Итоговый прогон: 5 тестов Vitest, 6 сценариев Playwright без повторов, 40 тестов API, 155 тестов matcher и 19 проверок бренд-системы. Проверка прозы прошла для README и новых документов; npm audit не сообщил известных уязвимостей runtime-зависимостей

## Отказы генерации

Живой прогон на локальной тестовой модели GigaChat 3.1 отклонил набор из-за отсутствующего обязательного факта в задачке: запрос требовал список городов без повторов. Это корректный отказ проверяльщика, а не успешное тестирование

Этот результат относится к локальной тестовой конфигурации. Облачный вариант DeepSeek Flash отдельно проверен на наборах генерации и ранжирования: результаты и ограничения находятся в [замерах taskgen](../taskgen/models.md) и [валидации matcher](../matcher/validation.md)

Проверка интерфейса берёт терминальное состояние из ответа API. При готовом наборе она требует выданные условия и редактор; при отказе требует объяснение, отсутствие редактора и отсутствие присвоенной категории. Такая проверка доказывает обработку исхода, а не гарантирует качество любого случайного ответа модели
