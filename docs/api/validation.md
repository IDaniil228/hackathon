# Проверка API

## Процедура

Проверка использует отдельные PostgreSQL БД, обычную runtime-роль API и роль matcher с его исходными grants. Тесты API проверяют HTTP-контракты и реальные ограничения БД, внешние сбои воспроизводят контролируемыми ответами

Проверяемые инварианты: чужие профили и приглашения недоступны, кандидат не подтверждает себе навыки, публичные контакты требуют opt-in, результат теста применяется один раз, провал не понижает категорию, потерянный POST не повторяется автоматически

PDF проверяется извлечением текста, кириллицей, многостраничным профилем и отсутствием скрытых контактов. Распознавание проверяется загрузкой реального сгенерированного PDF и отдельным подтверждением предложений

Команды воспроизведения — в [deployment.md](deployment.md)

## Результаты 2026-10-10

| Проверка | Результат |
|---|---|
| API: `pytest` с обычной runtime-ролью PostgreSQL | `32 passed` |
| Matcher: полный прогон против головы миграций API | `151 passed` |
| Taskgen: полный прогон на отдельной пустой БД | `1424 passed`, дополнительные LLM-проверки: 17 пропущены флагом, 1 тест боевого судьи исключён |
| Ruff lint и форматирование API, matcher и taskgen | Пройдены |
| API Alembic: heads и check | Одна голова `e0b53c4f2196`, расхождений с моделями нет |
| Сборка Docker API с замороженным lock | Пройдена, Python 3.13 |
| HTTP API → настоящий taskgen → настоящий matcher → приглашение → контакты → PDF | Пройден на отдельном стенде |
| LLM-разбор синтетического резюме через GigaChat | Имя, фамилия, город, телефон, стаж и навыки извлечены; проверяльщик подтвердил исходными строками |
| Визуальная проверка PDF | Логотип ФСП, брендовые цвета и шрифт, кириллица, переносы и нумерация страниц |

Обязательные проверки сервисов используют реальные БД и контролируемые внешние ответы. Дополнительные LLM-проверки не заменяют этот результат; настоящие модели отдельно проверены сквозным HTTP-сценарием и разбором резюме. Боевую доставку SMTP этот стенд не проверяет

Сквозной тест воспроизводится из `api/`: `uv run python tests/live_smoke.py --url <адрес отдельного стенда> --test`. Стенд использовал локальную GigaChat, подготовленный Piston и короткую конфигурацию taskgen: по одному заданию с кодом, эссе и тестовым вопросом, без снижения требования достаточности доказательства

Полная конфигурация taskgen сначала остановила сессию из-за незакрытого фрагмента условия, который GigaChat не исправила за предусмотренные попытки. API сохранил технический отказ без присвоения грейда и без расходования продуктового кулдауна; успешный короткий сценарий не доказывает безошибочную генерацию полного теста

## Проверка способности заметить дефект

В отдельных процессах проверки временно отключали принадлежность приглашения компании и подтверждение заявленного уровня. Тесты падали соответственно на раскрытии чужого приглашения и на ложном подтверждении грейда. Исходные файлы не изменялись, обычный прогон оставался зелёным

Детерминированные конкурентные тесты сначала воспроизвели восстановление отменённой попытки поздним GET и возврат оценённой попытки в submitted. После повторного чтения строк под блокировками оба дефекта исчезли
