# Контракт фронтенда

Спецификация [openapi.json](openapi.json) генерируется командой из [README API](../../api/README.md). Запущенное приложение отдаёт актуальный контракт по `/openapi.json`; бизнес-правила описаны в [архитектуре](architecture.md)

## Авторизация

Регистрация принимает роли `candidate` и `employer`, имена, почту, пароль и согласие на обработку данных. `admin` и неизвестные поля запрещены

`POST /auth/login` возвращает access token. Храните его в памяти, передавайте `Authorization: Bearer <token>`; refresh хранится в HttpOnly cookie. Запросы браузера используют `credentials: include`

В локальном режиме используйте одинаковое имя хоста для API и фронтенда: `localhost` с `localhost` либо `127.0.0.1` с `127.0.0.1`. Разные порты допустимы, но разные имена хостов мешают SameSite cookie и чтению CSRF cookie

Для `/auth/refresh` и `/auth/logout` передайте `X-CSRF-Token` из cookie `fsp_csrf`. Обновляйте токен через single-flight, не запускайте параллельные refresh. После перезагрузки страницы используйте refresh, затем `/me`

`/me` содержит роли, статус аккаунта, подтверждение почты и демонстрационные флаги. Аккаунт работодателя сначала создаёт компанию через `/companies`

В обычном режиме неподтверждённый аккаунт получает `403` на бизнес-операции, но может запросить письмо через `/auth/email/request` с полученным access token. В демонстрационном режиме этот endpoint может вернуть одноразовый токен вместо отправки письма

## Кандидат

1. `/me/profile`, `/me/preferences`, `/me/skills`, `/me/links` — анкета и самостоятельные заявления, без записи подтверждённого грейда
2. `/surveys` и `/surveys/{id}` — вопросы, `/surveys/{id}/submit` — ответы и самостоятельный выбор специализации и грейда
3. `/test-capabilities` показывает подключённые направления, навыки банка и наличие шаблонов; окончательные квоты проверяет taskgen
4. `POST /tests` с `survey_session_id` и уникальным `Idempotency-Key` возвращает сервисную операцию. `skill_ids` позволяет выбрать заявленные навыки для теста, `[]` запускает общий тест направления, `null` использует весь профиль; не выбирайте навыки вне подключённого банка
5. Опросите `/operations/{id}` до terminal state, затем `/tests/{resource_id}` до готовности заданий
6. Ответы отправляются в `/tests/{id}/tasks/{task_id}/answer`, завершение — `/tests/{id}/finish`, результат — `/tests/{id}/result`
7. Приглашения — `/invitations?cabinet=candidate`; переходы — `/invitations/{id}/view`, `/accept`, `/decline`

`insufficient`, сбой генерации и провал теста — разные состояния. Показать рекомендацию повышения можно, но изменять грейд на фронтенде нельзя. `/me/grades` хранит authoritative историю

## Работодатель

1. Создать компанию, затем потребность через `/needs`; опубликованная вакансия необязательна
2. `POST /needs/{id}/runs` с уникальным `Idempotency-Key` возвращает операцию, после успеха её `remote_id` — ID прогона
3. `/runs/{id}` — статус; `/runs/{id}/results` — готовая выдача с фильтрами и текущей приватностью
4. `/runs/{id}/refine` принимает сообщение и создаёт отдельную операцию нового прогона, старый не перезаписывается
5. `/needs/{id}/runs` — история; `/candidates` — каталог, не альтернативный алгоритм подбора
6. `/invitations` создаёт предложение с обязательной зарплатой и способом связи работодателя; передайте `Idempotency-Key`, чтобы повтор не создал второй оффер

Факторы и оценки выдачи относятся к моменту прогона. API скрывает сырой исторический текст, который мог содержать впоследствии закрытые поля. `factors` содержит разрешённые числовые компоненты, а `candidate` — текущую карточку

## Приватность

Отсутствующее поле означает, что API не разрешил его показать. Не восстанавливайте поле из предыдущего ответа или owner-профиля, не объединяйте карточки разных прав в общий кеш

Поле `contacts` появляется только при обычном раскрытии компании либо экспериментальном публичном режиме с отдельным согласием. Для обычного раскрытия кандидат должен разрешить `show_contacts`; принятие приглашения само по себе не отменяет этот выбор. Возможность публичного режима возвращает `/me`; переключатель выключен по умолчанию и отклоняется от ТЗ

Отзыв публикации исключает профиль из новых и старых подборок. После изменения прав перезапросите карточку и PDF, не используйте сохранённый blob как актуальный документ

## Документы и ФСП

`POST /me/resumes` принимает multipart `file`, возвращает документ и предложение распознавания. `/me/resume-parses/{id}/apply` переносит только выбранные поля и навыки, грейд не подтверждает

При `RESUME_LLM_ENABLED=true` распознавание использует модель и общий проверяльщик фактов со ссылками на исходный текст. `extraction_verified` означает проверку переноса, не подтверждение грейда или навыка. При недоступности модели или отказе проверяльщика остаются текстовые правила и справочник навыков. OCR отсутствует; повреждённый, зашифрованный или сканированный PDF получает явную ошибку

`/me/profile.pdf` — полный собственный PDF; `/candidates/{id}/profile.pdf` — версия работодателя. Исходный PDF доступен только владельцу

ФСП: согласие `fsp_data_sync`, `/me/fsp/demo-code`, `/me/fsp/link`, `/me/fsp/sync`, `/me/fsp`. Поле `demo` обязательно показывайте как демонстрационные данные, не называйте этот сценарий входом через FSP ID

## Дополнительные сценарии

- Вакансии: `/vacancies`, `/me/vacancies`, `/vacancies/{id}/status`
- Отклики: `/vacancies/{id}/applications`, `/applications?cabinet=...`, `/applications/{id}/{action}`
- Ручные задания: `/assignments`, `/assignments/{id}`, `/answer`, `/score`; они обновляют актуальность, не грейд
- GitHub App пока отсутствует

## Переписка

Работодатель может первым написать доступному кандидату. Первый контакт — `/invitations` с предложением и зарплатой; для связи только в чате укажите `contact_method=platform`, `contact_value` не нужен. После него `POST /invitations/{id}/conversation` открывает диалог сразу, без формального принятия приглашения. Оба участника могут повторить запрос открытия и получить прежний диалог

Первое сообщение имеет `kind=offer`, текст берётся из исходного приглашения. `offer` содержит условия предложения, поэтому кандидат видит зарплату до ответа. Ответ в переписке не меняет статус приглашения и не раскрывает контакты автоматически

- `GET /conversations` — собственные диалоги, счётчики непрочитанного и последние курсоры
- `GET /conversations/{id}` — предложение и состояние диалога, `can_send` указывает доступность отправки
- `GET /conversations/{id}/messages?after_id=...&limit=...` — сообщения после курсора, `next_cursor` и `has_more`
- `POST /conversations/{id}/messages` — `content` и уникальный `client_message_id` из `crypto.randomUUID()`; повтор с тем же текстом возвращает прежнее сообщение, иной текст под тем же ID даёт `409`
- `POST /conversations/{id}/read` — `{}` подтверждает все текущие сообщения, либо передайте `up_to_message_id` собственного диалога; простое чтение истории не отмечает сообщения прочитанными
- `POST /conversations/{id}/close` — любой участник закрывает диалог для новых сообщений, история остаётся доступна обоим

Для обновления чата опрашивайте сообщения с последним курсором, не скачивайте всю историю заново. Отображайте `content` обычным текстом, не исполняйте HTML из сообщения. Отклонение, отзыв или истечение предложения запрещает новые сообщения; принятие не требуется. Диалог доступен только кандидату и конкретному отправителю приглашения, не всем сотрудникам компании

## Сервисные операции и ошибки

`queued` — запрос сохранён, `running` — исполняется, `waiting_external` — API читает результат без повторной оценки, `reconciling` — восстанавливает результат по идентификатору операции, `succeeded` — завершён, `failed` — отклонён, `uncertain` — нужна сверка оператором

При `reconciling` продолжайте опрос операции: taskgen и matcher сохраняют её `request_ref` атомарно с ресурсом. При `uncertain`, например после смены сервисного ключа, не повторяйте действие с новым ключом автоматически

Ключ идемпотентности должен сохраняться для одного пользовательского действия. Тот же ключ с другим запросом возвращает `409`

Ошибки используют `detail`: `401` требует входа, `403` запрещает действие, `404` скрывает чужую или недоступную запись, `409` означает конфликт состояния, `422` — неверные поля, `429` — ограничение частоты, `502/503` — недоступность зависимости
