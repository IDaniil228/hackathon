# Категории, числа и масштабы

## Генерация

Опиши ситуацию в компании, где начинающий аналитик готовит признаки для задачи: {domain}. Назови конкретные признаки из легенды: несколько числовых и несколько категориальных. Расскажи по шагам, как он превратил категории в числа, какие модели обучает и что случилось после запуска. Пиши как нейтральный рассказ о его работе, без оценки

## Вопросы

1. Что не так с заменой категорий номерами по алфавиту для линейной модели? Для какой модели такое кодирование допустимо и почему?
2. Как правильно закодировать категориальный признак с небольшим числом значений? Покажите на признаке из ситуации.
3. Что делать с признаком, у которого 20 тысяч значений? Назовите не меньше двух способов и их риски.
4. Почему сервис падает на новых значениях категорий и как это предотвратить?
5. Нужно ли масштабировать числовые признаки для линейной модели и для случайного леса? Как сделать это правильно?

Ответ — развёрнутый текст на 10–20 предложений

## Факты

- task: аналитик готовит признаки для задачи: {domain}
- alphabet-codes: категориальный признак, у которого всего 5–10 значений, аналитик заменил номерами 1, 2, 3 и так далее по алфавиту
- many-values: один категориальный признак принимает около 20 тысяч различных значений
- models: аналитик обучает линейную модель и сравнивает её со случайным лесом
- unseen: после запуска стали приходить значения категорий, которых не было при обучении, и сервис падает с ошибкой
- scales: числовые признаки отличаются по масштабу в тысячи раз

## Нельзя раскрывать

- one-hot
- OneHot
- get_dummies
- target encoding
- handle_unknown
- ColumnTransformer
- ложный порядок
- фиктивн
- дамми

## Рубрика

- ordinal-problem: Объяснено, что номера по алфавиту вводят несуществующие порядок и расстояния между категориями, а линейная модель даёт признаку один коэффициент на "шаг" номера; для деревьев такое кодирование допустимо, потому что они делят признак порогами и могут выделить любую группу номеров несколькими разбиениями
  - "номера по алфавиту — нормальный способ для любой модели"
- one-hot: Предложено кодирование индикаторами (one-hot: `OneHotEncoder`, `pd.get_dummies`) с примером на признаке из ситуации; упомянута линейная зависимость столбцов для линейной модели без регуляризации и удаление одного столбца
  + "город → столбцы city_Москва, city_Казань, ... со значениями 0 и 1"
- high-cardinality: Для 20 тысяч значений предложено не меньше двух способов с рисками: объединение редких значений в "прочие", кодирование частотой, target encoding со сглаживанием и расчётом вне фолда, хэширование признаков, обучаемые векторные представления; назван риск утечки целевой переменной при target encoding
  - "one-hot на 20 тысяч столбцов" без оговорок о размерности и редких значениях
- unknown-categories: Объяснено, что кодировщик знает только значения из обучения; предложено `handle_unknown="ignore"` или категория "прочие", а кодировщик обучается на обучающих данных и сохраняется вместе с моделью
- scaling: Сказано, что линейной модели масштабирование нужно (регуляризация штрафует коэффициенты одинаково, оптимизация сходится быстрее), а случайному лесу — нет; параметры масштабирования считаются только на обучающей части, например в `Pipeline` с `ColumnTransformer`
