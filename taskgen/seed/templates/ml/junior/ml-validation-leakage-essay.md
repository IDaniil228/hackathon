# Переобучение и утечка данных

## Генерация

Опиши ситуацию в компании, где начинающий аналитик строит модель для задачи: {domain}. Расскажи по шагам, как он готовил данные, как разбил их, как подбирал настройки модели, на каких данных отчитался и что случилось после запуска. Пиши как нейтральный рассказ о его работе: каждый шаг выглядит обычным решением, без оценки.

## Вопросы

1. Почему качество на новых данных оказалось заметно ниже, чем на обучающей выборке? Как называется это явление и как его заметить по метрикам до запуска?
2. Найдите в работе аналитика все шаги, из-за которых оценка качества до запуска могла оказаться завышенной, и объясните механизм каждого.
3. Предложите правильную схему проверки модели: какие части данных нужны, зачем каждая и как подбирать гиперпараметры.
4. Когда случайное разбиение не подходит для этой задачи и чем его заменить?
5. Что можно изменить в самой модели, чтобы разрыв между обучающими и новыми данными уменьшился?

Ответ — развёрнутый текст на 10–20 предложений.

## Факты

- task: аналитик строит модель для задачи: {domain}
- boosting: аналитик обучил градиентный бустинг
- train-score: на обучающей выборке точность модели 0.99
- worse-after-launch: после запуска на новых данных качество модели заметно хуже
- impute-all: пропуски в признаках заполнены средним, посчитанным по всему набору данных до разбиения
- scale-all: признаки отмасштабированы с параметрами, посчитанными по всему набору данных до разбиения
- random-split: аналитик разбил данные на части случайно
- tuning-on-report: аналитик подбирал гиперпараметры по той же части данных, на которой потом отчитался итоговым качеством
- dated-records: данные копились несколько месяцев, и у каждой записи есть дата

## Нельзя раскрывать

- утечк
- переобуч
- Pipeline
- кросс-валидац
- k-fold
- GroupKFold
- TimeSeriesSplit
- разбиение по времени
- ранней остановк
- регуляризац
- оптимистич

## Рубрика

- overfitting: Переобучение определено как запоминание обучающих данных вместо общей закономерности, признак — большой разрыв между метрикой на обучении и на отложенных данных
  + "на трейне 0.99, на валидации заметно ниже — модель выучила шум"
- preprocessing-leak: Названа утечка через предобработку: среднее для пропусков и параметры масштабирования посчитаны с участием тестовых данных; правильно — считать их только на обучающей части, например внутри `Pipeline`
  + "fit скейлера только на train, transform на valid и test"
  - "масштабирование не влияет на качество, это не утечка"
- tuning-leak: Названа утечка через подбор гиперпараметров на той же выборке, по которой даётся итоговая оценка, и объяснено, почему оценка становится оптимистичной
- split-scheme: Предложена схема train/validation/test или кросс-валидация на обучающей части с отдельным тестом, который используется один раз в конце
  + "k-fold на train для подбора, test трогаем один раз"
- time-split: Для данных со временем или с группами объектов предложено разбиение по времени или по группам и объяснено, что случайное разбиение пускает будущее в обучение
  + "обучаем на январе–сентябре, проверяем на октябре" или `GroupKFold` по клиенту
- remedies: Названы способы снизить переобучение для бустинга: ограничение глубины и числа деревьев, ранняя остановка по валидации, регуляризация, больше данных
