# Устойчивость сортировки и выбор алгоритма

## Генерация

Составь вопрос из трёх частей на материале: {domain}. Опиши данные двумя полями записи: одно поле с небольшим числом различных значений (категория, день, отдел), другое — произвольное. Части вопроса:

1. Записи нужно упорядочить по первому полю, а внутри одинаковых значений сохранить порядок по второму полю, в котором они уже лежат. Попроси объяснить, что такое устойчивая сортировка, почему она здесь нужна, и как получить порядок по двум полям: одной сортировкой с составным ключом или двумя устойчивыми сортировками и в каком порядке.
2. Попроси назвать нижнюю оценку числа сравнений для сортировки сравнением и объяснить, при каком свойстве ключей можно сортировать быстрее, на примере поля с небольшим диапазоном значений.
3. Попроси рассказать, какой алгоритм использует встроенная сортировка Python (или другого языка на выбор кандидата), устойчива ли она и как она ведёт себя на почти упорядоченных данных.

Не подсказывай ответы в тексте вопроса. Ответ ожидается развёрнутым текстом на 10–20 предложений.

## Рубрика

- stable-definition: Дано верное определение устойчивости: элементы с равными ключами сохраняют взаимный порядок из входа
  + "при равных ключах записи остаются в том же порядке, что и до сортировки"
  - "устойчивая — значит работает за n log n в худшем случае"
- two-keys-order: Верно описан порядок двух устойчивых сортировок: сначала по второстепенному полю, затем по главному; или одна сортировка с составным ключом
  + "сначала сортируем по времени, потом устойчиво по авиакомпании" или `key=lambda r: (r.company, r.time)`
  - "сначала по главному полю, потом по второму" без составного ключа
- why-stable: Объяснено, почему при двух проходах вторая сортировка обязана быть устойчивой: иначе она разрушит порядок, полученный первой
- lower-bound: Названа нижняя оценка Ω(n log n) сравнений для сортировки сравнением, с объяснением через дерево решений или число перестановок n!
  + "листьев дерева решений не меньше n!, высота не меньше log2(n!) ≈ n log n"
  - "быстрее n log n отсортировать нельзя никак" без оговорки о сравнениях
- counting-sort: Предложена сортировка подсчётом или поразрядная для ключей из малого диапазона, с оценкой O(n + k) и указанием, что она не сравнивает элементы
  + "дней всего 31, считаем количество каждого и раскладываем за O(n + 31)"
- builtin: Верно описана встроенная сортировка: в Python это Timsort (с версии 3.11 — с правилом слияния серий Powersort), устойчивая, O(n log n) в худшем случае и близко к O(n) на почти упорядоченных данных за счёт поиска упорядоченных серий; для другого языка — столь же точные факты
  + "sorted и list.sort используют Timsort, он устойчив и использует уже упорядоченные куски"
  - "Python использует быструю сортировку, она неустойчива"
