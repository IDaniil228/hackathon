## Генерация

Опиши кейс в домене: {domain}. Команда должна упорядочить большой массив записей и перечисляет требования к сортировке. Опиши данные и требования так, как их обсуждала бы команда, в двух-трёх абзацах.

## Вопрос

Какой алгоритм сортировки лучше всего подходит под требования кейса?

## Варианты

### keep-order

Факты:
- data: записей несколько миллионов, ключ сортировки — момент времени с точностью до миллисекунды за последние десять лет
- equal: у записей с одинаковым ключом должен сохраниться их исходный взаимный порядок
- time: время работы должно быть O(n log n) даже в худшем случае

Ответ:
+ Сортировка слиянием
- Быстрая сортировка
- Пирамидальная сортировка
- Сортировка подсчётом

### small-keys

Факты:
- data: записей сто миллионов, ключ сортировки — целая оценка от 1 до 5
- time: важна только скорость, дополнительная память размером с массив допустима
- equal: записи с одинаковым ключом можно ставить в любом взаимном порядке

Ответ:
+ Сортировка подсчётом
- Сортировка слиянием
- Быстрая сортировка
- Пирамидальная сортировка

### tight-memory

Факты:
- data: записей несколько миллионов, ключ сортировки — произвольное дробное число
- memory: кроме самого массива, программа может занять лишь несколько переменных памяти
- time: время работы должно быть O(n log n) даже в худшем случае на специально подобранных данных
- equal: записи с одинаковым ключом можно ставить в любом взаимном порядке

Ответ:
+ Пирамидальная сортировка
- Сортировка слиянием
- Быстрая сортировка
- Сортировка подсчётом
