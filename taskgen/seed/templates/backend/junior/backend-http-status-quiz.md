## Генерация

Опиши кейс: {domain}. Клиент отправил запрос, и сервер должен решить, каким кодом ответить. Опиши запрос и состояние сервера так, как их увидел бы разработчик в логах и в коде обработчика.

## Вопрос

Каким кодом ответа HTTP по семантике RFC 9110 должен ответить сервер в этом кейсе?

## Варианты

### no-credentials

Факты:
- request: клиент запрашивает список своих записей в сервисе, а ресурс доступен только вошедшим пользователям
- auth: в запросе нет заголовка Authorization и нет никаких других учётных данных

Ответ:
+ 401 Unauthorized
- 400 Bad Request
- 404 Not Found
- 409 Conflict

### broken-body

Факты:
- request: клиент вошёл в систему и отправляет POST с телом в формате JSON
- body: в теле не закрыта фигурная скобка, и разобрать его как JSON невозможно

Ответ:
+ 400 Bad Request
- 401 Unauthorized
- 404 Not Found
- 409 Conflict

### missing

Факты:
- request: вошедший пользователь запрашивает методом GET одну запись по адресу с её номером 7781, и права на чтение таких записей у него есть
- state: записи с номером 7781 в базе нет и никогда не было

Ответ:
+ 404 Not Found
- 400 Bad Request
- 401 Unauthorized
- 409 Conflict

### stale-version

Факты:
- request: вошедший пользователь с правами на правку отправляет PUT с новой версией карточки, тело запроса корректно
- version: в запросе указан номер версии карточки 12, с которой пользователь начинал правку
- state: пока он правил карточку, коллега уже сохранил версию 13, и применить правку поверх неё сервер не может

Ответ:
+ 409 Conflict
- 400 Bad Request
- 401 Unauthorized
- 404 Not Found
