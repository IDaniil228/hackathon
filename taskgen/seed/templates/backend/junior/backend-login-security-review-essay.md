# Ревью функции входа

## Генерация

Придумай короткую легенду: команда делает продукт "{domain}" и перед выкатом просит коллегу проверить функцию входа по логину и паролю. Саму функцию покажут кандидату отдельно после твоего текста: не пиши код, не пересказывай его и не оценивай. Опиши команду и пользователей, скажи, откуда функция получает логин и пароль, и расскажи, как устроены база и журналы

## Вопросы

Функция, которую прислали на проверку:

```python
import hashlib
import logging
import sqlite3

log = logging.getLogger(__name__)


def login(db: sqlite3.Connection, username: str, password: str) -> bool:
    query = f"SELECT password_hash FROM users WHERE username = '{{username}}'"
    row = db.execute(query).fetchone()
    if row is None:
        log.info(f"login failed: user={{username}} password={{password}}")
        return False
    return row[0] == hashlib.md5(password.encode()).hexdigest()
```

1. Найдите уязвимости этой функции. Для каждой опишите, как ею воспользуется злоумышленник и что он получит.
2. Пришлите исправленную функцию и объясните каждое изменение.
3. Какие меры вне этой функции нужны, чтобы защитить вход?

Ответ — развёрнутый текст на 10–20 предложений с исправленным кодом

## Факты

- web-form: логин и пароль попадают в функцию прямо из формы входа на сайте в том виде, в каком их ввёл пользователь
- db-copies: разработчики выгружают копию базы пользователей себе на ноутбуки для отладки
- shared-logs: журналы приложения собираются в общий сервис логов, и читать их могут все сотрудники службы поддержки
- many-attempts: в журнале видно, что с одного адреса приходят тысячи попыток входа в час

## Нельзя раскрывать

- инъекц
- injection
- параметризован
- bcrypt
- scrypt
- argon
- PBKDF
- с солью
- без соли

## Рубрика

- sql-injection: Найдена SQL-инъекция: логин подставляется в запрос f-строкой; приведён пример ввода вроде `' OR '1'='1` или `admin' --`; исправление — параметризованный запрос
  + `db.execute("SELECT password_hash FROM users WHERE username = ?", (username,))`
  - "экранировать кавычки в логине вручную"
- weak-hash: Объяснено, что MD5 без соли быстро подбирается и вскрывается готовыми таблицами при утечке копии базы; предложены bcrypt, scrypt, Argon2 или PBKDF2 с солью и настраиваемой стоимостью
  - "заменить MD5 на SHA-256" без соли и медленной функции
- password-in-logs: Найден пароль в журнале: его видит каждый, у кого есть доступ к логам; пароль не пишется в журнал никогда
- constant-time: Сравнение хэшей сделано через функцию проверки из библиотеки хэширования паролей или `hmac.compare_digest`, с объяснением, что обычное сравнение строк выдаёт разницу по времени
- fixed-function: Приведена исправленная функция, в которой устранены все найденные уязвимости и нет новых
- outer-measures: Названы меры вне функции против перебора и кражи паролей: ограничение числа попыток по адресу и по учётной записи, задержки или капча, HTTPS, двухфакторная аутентификация, оповещение о подозрительных входах
  - "попросить пользователей придумывать сложные пароли" как единственная мера
